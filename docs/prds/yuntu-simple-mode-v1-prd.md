# 云吞吞「简单模式」- 产品需求文档（PRD）

> 需求原话（小徐 2026-10-04 19:10）：
> ①「循序渐进模式不用动,新增用户默认为简单模式「中文正文混词库英文单词」」
> ② 修正「不是新增用户默认值,是当前所有用户默认值改为简单模式(除了当前在沉浸模式的)」
>
> 澄清定案（2026-10-06 两轮）：密度 A（每轮 3-6 词、复习词优先）；仅「全沉浸」用户保留（显式选过渐进的一并切简单）；开场用预烤中文译文嵌词、零 AI；全语种通用（en 混英文词 / ja 混日文词 / ko 混韩文词）；嵌入词高亮可点查；正文 ≈150-300 中文字/轮。

## 一、需求描述

### 背景
- **业务问题**：现有两档沉浸模式（渐进沉浸/全沉浸）都要求用户能读目标语原文，零基础用户的第一道门槛就是"满屏外语"。需要一个最低门槛入口：读得懂（中文为主），又能自然接触目标语词汇。
- **目标用户**：全量玩家。简单模式成为**新的默认模式**；仅显式选择过「全沉浸」的用户保留原设置。
- **价值**：零压力起步——剧情体验不受影响，词汇在语境中反复自然复现（含复习词优先回投），为进阶到渐进沉浸铺路。

### 功能概览
- **核心功能**：新增第三种沉浸模式 `immersion = "simple"`——中文剧情正文中自然嵌入词库目标语单词；全量用户默认切换；三语种（en/ja/ko）通用；开场零 AI 中文化。
- **边界（不做）**：
  - 不改「渐进沉浸」「全沉浸」的任何行为（提示词、状态机、阈值都不动）；
  - 不影响非语言卡（中文剧情卡、恋爱卡等 `structured.band` 为空的卡）；
  - worker.js / 后端无需改动；
  - 不做新的硬性生成质量检测（以提示词约束为主）。

### 用户场景
1. 新用户注册后第一次玩语言卡：默认即简单模式，开场就是"中文剧情+高亮单词"，点词即查。
2. 老用户（没设置过模式）升级后：自动进入简单模式；想加深难度可随时在设置里切渐进/全沉浸。
3. 全沉浸用户：升级后设置保持全沉浸不变。
4. 日/韩学习者：同样默认简单模式——中文正文里混入日文词（假名优先）/韩文词。

## 二、详细需求

### 2.1 模式语义
| 模式 | 值 | 正文 | 每轮词汇 | 双语行 |
|---|---|---|---|---|
| 简单模式 | `"simple"` | **中文**为主体 | 自然嵌入 **3-6 个**目标语词（复习词优先） | 无 |
| 渐进沉浸 | `"progressive"` | 目标语（现状：前2轮 scaffold 带双语，第3轮起 fade 纯目标语） | 现有机制 | 有（现状） |
| 全沉浸 | `"full"` | 目标语纯正文（现状） | 现有机制 | 无（现状） |

- 每轮长度：**≈150-300 个中文字**，数段、对话独立成行、开场 in medias res（沿用现有叙事规范）。
- 混入词来源：① 用户生词本复习取样（`reviewVocabSample(10)`，SRS 到期优先）→ ② 卡档词库候选（`getChapterWords`，扩容后 ≤8）。总数不超过 6 个实际嵌入，允许"不适配就少用/跳过"。
- 语种细则：
  - **en**：英文单词原形/通用变形，如 `点了一杯 coffee`。
  - **ja**：优先假名词（コーヒー）；必须是汉字词时附假名注音，如 `走进 喫茶店（きっさてん）`。
  - **ko**：韩文（hangul）词，如 `去 カ페… → 카페 喝咖啡`（韩文词天然可辨，无注音需求）。

### 2.2 默认值与迁移（关键）
- **默认值**：未设置用户（`profile.immersion` 为空）的默认行为从 `progressive` 改为 `simple`。
  - `lang-play.js:339` picker 高亮 fallback：`|| "progressive"` → `|| "simple"`（改为统一走"有效模式"函数）。
  - `app.js:17093` immStage fallback：`p.immersion === "full" ? "full" : "progressive"` → 按 2.2 规则返回 simple。
- **一次性迁移**（升级后全量用户）：
  - `full` → 保留 `full`；`progressive`（显式选过）→ 改 `simple`；空 → `simple`。
  - 引入版本标记 `profile.imm_v = 2`（迁移前无此字段）。迁移幂等：仅在 `imm_v` 缺失时执行。
  - **迁移后用户重新选择渐进沉浸 → 保持渐进**（`imm_v>=2` 时如实生效，不再被反复重置）。
- **云档同步**：
  - `saveRemote` body 增加 `imm_v: profile.imm_v || 0`（`lang-play.js:252` 附近）。
  - 云合并规则（`lang-play.js:325` 附近）改为带版本仲裁：仅当云端 `imm_v >= 本地 imm_v` 时采纳云端模式值；**防止旧缓存客户端把陈旧 `progressive` 回灌覆盖迁移结果**。
  - 迁移函数单点实现（app.js `readProfile` 附近，含 LangEngine 与 LangPlay 两侧启动时各调一次、幂等），迁移后 `save()` + `saveRemote()`。

### 2.3 生成侧（buildInjection，`app.js:17197`）
- `immStage(round)` 扩展第三分支：`{ mode: "simple" }`（优先级：full > progressive(imm_v≥2) > simple）。
- 简单模式下的提示词块（替换/降级 LANGUAGE LOCK 语义）：
  - 明确「title/story/options 一律用自然中文书写」（中文在此模式下**合法且必要**）；
  - 每轮从候选清单（复习词在前）自然嵌入 3-6 个目标语词，语境优先、不胜硬塞；
  - ja 卡附加：优先假名写法；汉字词后附假名「（かな）」；
  - `story ≈150-300 中文字`；对话独立成行；
  - **不输出 `bilingual` 字段**；正文除目标语词外保持纯中文、不夹其他语种。
- 候选注入：复用 `reviewVocabSample(10)` + 扩展词库候选接口（见 2.5）。
- 违规检测（`hasLanguageViolation`，`app.js:17168`）：`targetLang` 会话 + `stg.mode === "simple"` 时**直接跳过 CJK 违规判定**（中文合法）；`buildLanguageFixPrompt`（`17187`）在简单模式不触发。渐进/全沉浸路径零改动。

### 2.4 开场（第 1 幕）——本地转换、零 AI
- 有预烤双语（`structured.first_scene.bilingual.lines[{text, zh, words[{w,zh}]}]`）的卡：本地把每行**中文译文 `zh` 作为正文**，将其 `words` 里"中文义命中 `zh` 文本"的词替换嵌入首个出现处：
  - en：替换为 `w`；ko：替换为 `w`；ja：替换为假名形/带读音形（见 2.5 预烤补充）。
  - 未命中（zh 不含该中文义）→ 该词不嵌入，整行保持纯中文。
  - 嵌入词高亮可点（见 2.6）；不显示英文原文行、不显示行间译文。
- **无预烤双语**的卡（现状：10 张日/韩卡全缺，个别英语老卡可能缺失）：
  - 方案 A（本 PRD 采用）：**一次性批量补烤**——用现有 `scripts/prebake_first_scene.mjs` 对缺卡跑一遍（切句→gloss→zh+词注落盘），开场全覆盖、仍零 AI；
  - 兜底：仍未命中（新卡漏烤）→ 简单模式首轮改由 AI 按简单模式风格生成（从"零 AI 开局"降级为首轮 AI，可接受）。

### 2.5 数据与接口扩展
- `profile.immersion` 值域：`undefined | "simple" | "progressive" | "full"`；新增 `profile.imm_v`（number，迁移版本）。
- **LangAssist 候选扩容**：现 `getChapterWords()` 注入上限 ≤3 且带"注入即推送（pushed）"状态位（`lang-aux.js:785`）。新增只读接口 `getSimpleCandidates(limit)`（词库抽样 ≤8，不改 `pushed` 语义、不影响渐进沉浸注入链），简单模式提示词用 `getSimpleCandidates(8)` + `reviewVocabSample(10)`。
- **预烤脚本补充**：
  - 对 10 张 jp-/kr- 卡 + 任何缺双语卡补烤 `first_scene.bilingual`（幂等，已有则跳过）；
  - ja 卡词注可补充假名读音字段（`words[].reading`，如 `喫茶店/きっさてん`）供开场注音；gloss 来源无法提供读音时，该词开场直接嵌原形（不注音，可接受——点查仍可见假名释义）。
- PB 数据更新走既有 `pb_import_lang_card.mjs` 幂等 upsert（仅结构化字段变化，不动 status/封面）。

### 2.6 渲染侧（阅读界面）
- 正文渲染在简单模式下开启「目标语词高亮」层：
  - 识别：en = 拉丁词 token；ja = 假名连缀、及"汉字词（假名）"整体；ko = hangul 连缀；中文文本不高亮。
  - 交互：点击高亮词 → 复用现有单词点查/词卡链路（词库命中给词义；未命中走现有降级）。**无行内中文提示、无自动展开译文**。
  - 收集行为：与现有查词一致（可收藏入生词本，复用现有机制，不新增自动入库）。
- 辅助面板（LangAssist）：简单模式下不自动展开任何译卡，全部手动触发。
- 学习统计：时长口径不变（不区分模式）；不做模式专属统计。

### 2.7 UI（设置项）
- `index.html`（约 L486-495）沉浸模式 picker 增加第三个按钮，顺序与文案建议：
  1. **简单模式**（`data-m="simple"`，带"推荐"徽标）——「中文剧情里自然认识单词，零压力起步」
  2. 渐进沉浸（`data-m="progressive"`，去掉"推荐"徽标）——「译文随剧情推进逐渐退场」
  3. 全沉浸（`data-m="full"`）——「纯目标语体验，辅助全部手动触发」
- `renderPicker`（`lang-play.js:337`）高亮逻辑走"有效模式"函数（迁移后：full 显 full，其余显存储值/默认 simple）。
- `setImmersion`（`lang-play.js:452`）写入时确保 `imm_v = 2`（用户迁移后再选择也带版本）。

### 2.8 边界与异常
- 进行中的存档：模式切换即时生效于**下一轮生成**（与现有 progressive/full 切换行为一致），不重写历史轮次。
- 已购/试玩门（/story/pp6）等非站内卡链路**不受影响**（那是独立产物，不含 immersion 逻辑）。
- 未登录/离线：迁移在本地完成，`saveRemote` 失败静默（现有行为）；下次联网合并按版本仲裁。
- 语言卡但非目标语会话（如中文卡）不触达本逻辑。

## 三、设计决策

### 技术方案
- 全部为**前端改动**：`assets/app.js`（immStage / buildInjection / 违规检测 / 迁移函数）、`assets/lang-play.js`（默认值 / picker / 云档）、`assets/lang-aux.js`（候选接口 / 高亮识别）、`index.html`（picker 按钮）。
- 单点状态机：`immStage` 一处定义三种 mode，生成侧/渲染侧/高亮共用（沿用 M7a 架构原则）。
- 预烤与 PB 更新为一期一次性离线任务（脚本），不引入运行时成本。
- 部署：`?v=` bump（app.js / lang-play.js / lang-aux.js / index.html）+ `git push origin main:main` + `ssh pb "cd /var/www/bitlife && git pull origin main"`；worker 无需部署。

### 约束
- 「渐进沉浸/全沉浸」行为零变化（回归红线）；
- 开场保持零 AI（有预烤数据时）；
- 不改动 worker、PB schema、卡与封面资产；
- push/上线属影响全量用户的操作，**需小徐明确授权后执行**。

### 风险
| 风险 | 说明 | 缓解 |
|---|---|---|
| 混词生硬/密度失守 | 模型可能塞词或超量 | 提示词限定候选+数量；观察期 2-3 轮调参；密度为参数不写死 |
| 老用户被"重置"感 | 显式选过渐进的用户被切简单 | 按小徐决定执行；picker 常驻可一键切回；迁移后不再覆盖 |
| 旧客户端回灌云档 | 缓存旧 JS 推旧值覆盖迁移 | `imm_v` 版本仲裁合并规则 |
| 存量卡无预烤双语 | 10 张 ja/ko 缺数据 | 一次性补烤；残留兜底=首轮 AI |
| ja 汉字词辨识弱 | 汉字词看着像中文 | 假名注音规则；预烤补读音 |
| 中文正文误高亮 | 高亮层吃到中文/其他 token | 识别规则按目标语字形白名单；探针覆盖 |
